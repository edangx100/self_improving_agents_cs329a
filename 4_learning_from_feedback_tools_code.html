Learning from Feedback with Tools and Code

An agent gets better by taking seriously what came back to it — an answer from a tool, a failing test, or a critique it wrote about its own reply.

A language model, left alone, produces text and stops. It cannot check whether the fact it just stated is true, whether the program it just wrote runs, or whether the advice it gave was a bad idea. Everything it says is a guess assembled from what it read during training, and a fluent guess looks exactly like a correct one.

This lesson is about closing that gap by letting something outside the model answer back. Three papers, three sources of that answer: a tool that knows something the model does not, a test suite that runs the code, and a written set of principles the model applies to itself. What separates them is not the loop — the loop is the same — but where the answer comes from, and how deep into the model it goes.

1

Why a model needs something outside itself

Chain-of-thought prompting made models visibly better at showing their work, and it created a specific illusion. The steps are written out, they are legible, and they are still invented from memory. If the model goes wrong at step three, nothing intervenes. The error simply propagates through the remaining steps, dressed in the same confident prose as everything else.

The plainest version of the problem is knowledge the model does not have. Ask Gemini, ChatGPT, or Claude about something that happened after its training data ends and it has nothing to work with unless it goes and searches. The model cannot tell the difference between recalling and confabulating, and asking it how sure it is does not help much — models are generally overconfident and poorly calibrated about their own knowledge.

The stance the lecture takes
Rather than trying to get the model to report its own uncertainty accurately, give it a tool and let the tool settle the matter. Grounding beats introspection.

So the design question becomes: what can answer back, and what happens to the answer once it arrives? The rest of this page is three answers to that, arranged roughly in order of how much external ground truth each one requires.

2

ReAct: think, act, and look at what came back

ReAct (Yao et al., 2022) changes the shape of the trace. Instead of one uninterrupted chain of reasoning, the model alternates between three kinds of line: a thought about what it needs next, an action that goes and gets it, and an observation handed back by the environment. The two halves help each other. Reasoning lets the model plan a sequence of actions and recover when one surprises it; acting keeps the plan attached to information it did not make up.

The example the lecture works through is a HotpotQA question that cannot be answered in one hop: what else can control the program the Apple Remote was originally designed for? A single chain of thought has to guess. ReAct looks up the Apple Remote, learns the program is Front Row, then looks up Front Row.

Two details are worth noticing. The first is that this was demonstrated with a frozen model and one or two examples in the prompt: no training, just a format. The second is that ReAct was originally implemented in the era of PAL and similar prompting work, before tool calling was built into models. Today's models do much of this implicitly, which makes ReAct less a technique to apply than an abstraction to reason with — someone still has to decide, for each new domain, what counts as an action and what an observation looks like.

3

What the loop bought, and where it strains

On question answering and fact verification, interleaving actions cut down hallucination and error propagation, because a claim the Wikipedia lookup does not support is visible as such in the trace. On interactive tasks the margin was wider: on ALFWorld, the best ReAct trial reached 71% average success against 45% for acting without reasoning, and ReAct beat imitation and reinforcement learning baselines by 34 points of absolute success rate there and 10 points on WebShop.

WebShop is the more sobering of the two. The agent is given a shopping instruction and has to search a cluttered catalogue, open products, choose options, and buy.

Four places it strains

  • Large action spaces. The more the agent could possibly do, the more demonstrations it needs to learn the format — and demonstrations compete for the same context window as the task.
  • Cost. Every reasoning step is more tokens and more latency, paid on every episode.
  • Noisy or misleading observations. The loop assumes the environment tells the truth. When it does not, you need a reflection step that reasons about the input itself, and some way to back out of a path already taken.
  • Knowing when to stop. Confidence has to come from somewhere other than the model's self-report. Running the same task repeatedly and comparing outcomes is one of the few measures available.
Where this is heading
The lecture expects hand-written workflows like ReAct to matter less as reinforcement learning improves, because a trained model can discover its own action sequences. What survives is the workflow definition — and in domains where the search space is hard to specify in general, that definition is still the valuable part.
4

RLEF: when the tests are the reward

Code is unusual among the things we ask models to produce: you can run it. That makes the feedback exact, cheap, and available in unlimited quantity — the ideal case for the dashed return path in the first diagram.

The problem RLEF (Gehring et al., 2024) addresses is that strong models do not naturally use it. Show a model its own failing test output and ask it to fix the program, and it often does no better than if you had thrown the attempt away and sampled a fresh one. The feedback is present in the context and is not being exploited. Nothing ever trained the model to carry information across turns.

RLEF fine-tunes on the multi-turn conversation end to end. The model writes a solution, the solution is executed, results return into the dialogue, the model revises. Where the design gets careful is in which tests it is allowed to see.

Why the split matters

If the model could see the tests that determine its reward, it would learn to satisfy those particular cases — special-casing inputs, hard-coding outputs, memorising instead of solving. Holding the private set back keeps the reward honest. It is the same logic as not training on your test set, applied inside a single episode.

The reward itself is blunt: pass or fail, a single bit. That turns out to be enough for competitive programming, though the lecture notes that harder problems may eventually need something richer than a binary — which test failed, and how.

The results are reported on Llama 3.1 at both 8B and 70B, reaching state-of-the-art performance on CodeContests while requiring an order of magnitude fewer samples than before. That reduction is the practical headline. Repeated sampling can brute-force a great deal, but it is expensive; a model that reads its own error and makes a targeted edit arrives with far fewer attempts, and the improvement carried over to benchmarks it was not trained on.

The question from the room
Real software does not fit in a context window. Asked how this extends to a large codebase, the lecture points at the working answers rather than a solved one: summarise rather than paste, use search to retrieve only the relevant parts, or represent the repository as a graph. SWE-bench is the benchmark shaped around exactly that pair of problems — find the relevant code, then edit it.
5

Constitutional AI: feedback with no one left to ask

Execution feedback works because correctness is checkable. Harmlessness is not. Whether a response is manipulative, or cruel, or quietly encouraging something dangerous, has traditionally been settled by paying people to compare pairs of responses — accurate, broad, and impossible to scale as models improve faster than labels can be collected.

Constitutional AI (Bai et al., 2022) moves the human contribution upstream. People write a short set of principles — avoid harmful or unethical content, be respectful, and so on. The model does everything after that.

The trade-off, and why reasoning helps

Harmlessness and helpfulness pull against each other. A model that refuses more is safer and less useful, and the crude version of this training makes exactly that trade. The finding worth keeping is that the frontier itself can move: having the preference model reason step by step before judging produced the best balance of the two, better than standard reinforcement learning from human feedback.

Nothing about the mechanism is specific to safety. Any setting where a model must follow a written set of rules — especially rules that sometimes conflict with each other — can use the same critique-and-revise loop, and generalising it beyond harmlessness is an open research direction the lecture flags as a project idea.

The problem that stays open
Principles get amended. Getting a model to stop following a rule it has already absorbed, without retraining from scratch, is a continual-learning question with no clean answer — and a governance problem as much as a technical one.
6

Where the feedback lands

Reading the three papers together, two independent questions separate them. First, can anything outside the model decide whether the output was good? Second, does the verdict change only this reply, or does it change the model?

Four things to carry forward

  • Feedback in the prompt and feedback in the weights are different tools. ReAct improves an episode; RLEF and Constitutional AI improve the model. Only the second kind compounds.
  • Separate what the model sees from what it is scored on. The public/private test split is the cheapest defence against a model that learns the benchmark rather than the task, and the principle generalises well beyond code.
  • A blunt reward can be enough, until it is not. Pass or fail carried RLEF to state of the art. Whether outcome rewards or process rewards are right for longer, messier problems is still contested — denser signal costs judgements you may not be able to make.
  • Model-generated feedback needs a confidence measure it does not yet have. Self-reported certainty is unreliable; repeated execution and agreement across attempts is the more honest signal, and it is expensive.
The closing discussion
The lecture ends on cognitive science. The loop in these three papers — try, look, revise — is a rough sketch of something people do fluently, and the sketch is still crude. Where an agent's capability ends and its scaffolding begins, once memory and sessions are added around the model, is increasingly the more interesting question.
